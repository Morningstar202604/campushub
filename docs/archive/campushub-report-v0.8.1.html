01

项目概览

Overview

CampusHub 是一个基于 uni-app 三端（微信小程序 / H5 / 安卓 APK）+ 微信云开发（CloudBase） 的开源校园内容社区。采用「一校一部署」模式：每个学校/组织独立部署一套云环境，学生在多级分类树下发帖、提问、交易、互动。

  • 一套代码 · 三端交付：uni-app（Vue 3 + Vite）共用 20 个页面与全部业务逻辑，小程序走 wx.cloud.callFunction，H5/App 走 CloudBase REST（restToken）。
  • 37 个业务入口收敛到 10 个部署单元：7 个资源型网关（auth/post/product/comment/social/admin/content）+ 3 个独立函数（2 定时器 + 1 初始化）。
  • 共享内核层（9 模块）：通过 build:functions（esbuild）在构建期内联进各函数产物，单一数据源，副本漂移在结构上不可能（历史 333 份重复代码已消除）。
  • 安全优先：所有 UGC 经微信 msgSecCheck/imgSecCheck，fail-closed（任何异常即拒绝发布）。
  • 近零成本：云开发免费额度起步，生产环境 19.9 元/月起。
核心设计哲学可概括为：三端同源 · fail-closed 内容安全 · 原子限频 · 查询白名单 · 集中封禁 · 单一删除入口 · 定时任务守卫。整套代码已无 TODO/FIXME 技术债、无硬编码密钥、所有 handler 经 wrap() 统一错误处理。

核心安全原则（逐条对照源码实现）

  • Fail-closed 内容安全：checkImage 下载 cloud:// 文件转 Buffer 后调 imgSecCheck；任何异常/超限/违规一律拒绝发布，不让未检内容通过。
  • 原子限频（v0.9.2）：rate_limits 确定性 _id 占位 + _.inc 原子自增，主键唯一性保证窗口内恰一次放行，杜绝并发 TOCTOU 绕过。
  • 查询面白名单：sanitizeQuery 字段白名单 + 标量断言，防对象/操作符注入。
  • 集中封禁：requireActiveUser() 在 21 处统一拦截写操作，封禁检查不在各函数里散落。
  • 单一删除入口：removeContent() 统一处理软删 + 云存储图片回收 + _.inc 计数原子回退 + reconcileUserCounts 对账。
  • 定时任务守卫：backup-db/task-expire fail-closed——定时触发放行，手动调用仅限管理员；init-db 校验 INIT_SECRET。
  • 分类路径服务端推导：resolveCategoryPath 由服务端从分类树推导，防客户端伪造 categoryPath。
  • 幂等：clientReqId + 唯一索引实现首次登录/发帖/点赞幂等，防重复提交。

结论与建议

Conclusions & Recommendations

优势 / 亮点

  • 架构收敛到位：37 入口→10 单元，共享内核单一数据源，副本漂移从结构上杜绝。
  • 安全默认 fail-closed：内容审核、管理员判定、定时守卫全部失败即拒绝，无“放行兜底”隐患。
  • 并发安全：限频原子化 + 计数 _.inc 自修复，避免超发与计数漂移。
  • 工程纪律强：门禁一键可跑、ESLint/Prettier 入库强制、零 TODO、零硬编码密钥。
  • 可运维：init-db 索引自检、每日备份、日志生命周期管理齐全。

观察 / 建议

  • 密钥注入方式：ADMIN_OPENIDS、INIT_SECRET、部署私钥均走环境变量/CI 注入，未硬编码——建议持续保持，并监控 ADMIN_OPENIDS 是否过大扩散。
  • 前端 REST 凭据：H5/App 走 restToken，需注意小程序端 appid 与云环境绑定关系，避免跨环境误配。
