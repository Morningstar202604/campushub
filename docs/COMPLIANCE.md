# 合规与主体路径指南（COMPLIANCE）

> 面向**个人开发者 / 校园开发者**的上线合规指引。核心结论一句话：
> **个人主体做不了"社区 / 论坛"类目（UGC 公开内容流），想上微信审核，请升级为「个体工商户」主体（个人可办），或把产品收敛为「信息查询 / 校园服务工具」形态。**

本文件不是法律意见；微信类目、备案政策会调整，**以微信公众平台 / 开放社区实时查询为准**（官方入口见文末）。

---

## 0. 一句话结论（先记住）

| 你想怎么上线 | 能否用个人主体 | 建议 |
|---|---|---|
| 完整 UGC（公开发帖、匿名、信息流、评论） | ❌ 不行 | 办个体工商户（个人可办，成本低）→ 走【社交-社区/论坛】类目 |
| 收敛形态（信息查询、预约、校园服务工具，不公开传播 UGC） | ✅ 可以 | 个人主体选「工具 / 教育信息服务」类目，功能做裁剪 |
| 学校/社团名义 | ⚠️ 看学校 | 学校作为主体或挂靠学生组织，需学校盖章配合，多数情况不现实 |

> 官方原话（微信开放社区，2026-07）：**"若涉及用户生成内容(UGC)，需使用企业主体小程序，个人主体无法申请该服务类目"**（【社交-社区/论坛】类目）。这就是你上轮"类目选不了社区/论坛"的原因。

---

## 1. 路径 A：办个体工商户（推荐，一劳永逸）

个体工商户 = 非个人主体，**个人凭身份证即可注册**（无需注册公司、无需验资），就能解锁【社交-社区/论坛】类目。

| 步骤 | 做什么 | 时长/成本 |
|---|---|---|
| 1 | 到**当地政务服务网 / 市场监督管理局**在线申办「个体工商户营业执照」（经营范围写"软件开发；信息技术服务；互联网信息服务"等） | 0~几天，费用 0（多数地区免费） |
| 2 | 用个体户执照注册/变更微信小程序主体（个人→个体户） | 1~3 天审核 |
| 3 | 选择类目【社交-社区/论坛】 | 需同时满足下面第 2 节备案要求 |
| 4 | 按第 2 节完成 ICP 备案 + 内容安全配置 | 1~4 周 |

> 如果只是校园内部小范围使用、暂不对外公开，也可以**先以「体验版」跑通功能**（体验版不要求类目），再在正式上线前办主体。

## 2. 备案（个体户/企业必须，个人主体一般也要）

微信小程序上线需完成**小程序备案**（在微信公众平台后台直接在线办理，与网站 ICP 备案同源）。

- 入口：公众平台 → 设置 → 基本设置 → 小程序备案
- 备案主体需与**小程序注册主体完全一致**（个人备案主体就是你的身份证）
- 个人主体命名限制（官方）：名称**不得**含企业/单位名义（如"XX公司"）、前置审批领域（新闻/金融/宗教/医疗器械/网约车/校外培训等）、国家公共事务（监管/政务/政府等）关键字；不得超出个人经营范围（如"商城、商贸"）
- 时长：约 1~4 周（各省管局不同）

## 3. 改名示例（避开审核雷区）

小程序名别带"社区 / 论坛 / 吧 / 集市 / 商城"等字眼（这些词会触发类目与经营范围校验）。

| ❌ 不建议 | ✅ 建议 |
|---|---|
| XX校园社区 / XX校园论坛 / XX大学贴吧 | XX校园信息助手 |
| XX校园集市 / XX校园商城 | XX校园生活服务 / XX校园二手助手（个体户可加"二手"） |

> 名称改完，**文档与落地页**也建议同步收敛（本仓库 README / index.html 已按此调整，见第 6 节）。

## 4. 隐私政策（必须配置）

微信要求小程序必须配置《用户隐私保护指引》（公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引），**代码里要主动声明用到的隐私接口**：

本项目的隐私接口声明建议（在指引里勾选/填写）：

| 接口/信息 | 本项目用法 | 是否使用 |
|---|---|---|
| 微信登录（openid） | 自动注册与身份识别 | ✅ 已用 |
| 用户头像 / 昵称 | 个人资料展示（用户自行填写） | ✅ 已用 |
| 相册（保存图片） | 「分享海报」保存到相册 | ✅ 已用 |
| 地理位置 | — | ❌ 未用（不要勾选） |
| 手机号（getPhoneNumber） | — | ❌ 未用（个人主体也用不了） |

> 隐私政策模板要点：收集哪些信息、用途、保存期限、如何删除账号数据、联系方式。可参考微信官方《小程序隐私政策模板》。

## 5. 身份认证兜底（个人主体特别提醒）

- 个人主体小程序**无法调用 `getPhoneNumber`（手机号快捷验证）**，也无法用微信昵称一键授权（`wx.getUserProfile` 已下线）。
- 本项目**登录不依赖手机号/昵称授权**：`app.js` 用 `wx.login → openid` 自动注册，昵称头像由用户**自行填写/上传**，天然规避了这两项限制。
- 如需"学生身份"核验（例如仅校内开放），建议用**学号 + edu 邮箱 / 学校邮箱** 做人工核验（在管理后台 `verify_requests` 已支持提交认证申请），不要依赖手机号接口。

## 7. 个人主体"能过审"的功能裁剪方案（如果坚持个人主体）

个人主体若想上线，需把"公开 UGC"收敛为"个人工具"，可按需裁剪（保留哪个取决于你）：

| 保留（个人可做） | 建议移除/关闭（触发 UGC 类目） |
|---|---|
| 指南文章、校园信息查询 | 公开信息流首页（所有人都能看到所有帖子） |
| 二手交易（需个体户） | 匿名发帖、公开评论楼中楼 |
| 预约/报名（工具类） | 关注、动态流、搜索全站内容 |

> 最省事的替代：**只保留"校园指南 + 通知 + 工具"**，去掉发帖/评论/二手，走「工具-信息查询」或「教育-教育信息服务」类目，个人主体即可过审。业务价值缩水，但零主体成本。

## 8. 上线检查清单（最终提交审核前）

- [ ] 主体类型已确认（个人裁剪版 / 个体户完整版）
- [ ] 小程序名称符合主体性质（不涉及企业/前置审批/政务字样）
- [ ] 已选可用类目（个人：工具/教育信息服务；个体户：社交-社区/论坛）
- [ ] ICP/小程序备案已通过
- [ ] 《用户隐私保护指引》已配置并声明所用接口
- [ ] 已按 docs/DEPLOY.md 完成内容安全 API 配置（UGC 必检）
- [ ] 已按 docs/OPERATIONS.md 配置自动备份 + 管理员审计日志（backup-db / admin_logs）
- [ ] 已配置管理员 `ADMIN_OPENIDS`，并设 `INIT_SECRET`（防止 init-db 被恶意调用）
