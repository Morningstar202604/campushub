### 6.2 复核建议中判定不修（附证据）

- **「admin unban 应恢复 approved」**：grep 全仓 `verifyStatus` 仅取值 `unverified`（login 建档）/ `banned`（封禁），**不存在 `approved` 枚举**；校园认证由 `campusVerified` 布尔 + `campusVerifyStatus` 承载，ban/unban 均不触碰，解封后认证态无损——判误报，维持原实现。
- **「product-update 枚举白名单会误拒存量枚举外数据」**：App 内编辑预填已归一化枚举（含兜底 `'other'`），仅绕过前端直写 API 的历史数据会被拒——正常用户零误伤，不修，记录在案。
- **「backup-db 分片上限过紧」**：维持 2 万条/集合上限（防定时任务失控），截断改为显式 `truncated` 标记交运维感知，不提高上限。

### 6.3 残余已知项（如实告知）

- rateLimit max>1 场景「自增后回读」存在同值竞态，窗口内超限量 ≤ 并发数（原实现为无界放行，已收敛数量级）；固定窗口边界处最多 2×max 突发（原滑动窗口无此特性），取舍已注释于 common-rate.js。
- admin ban 不联动 `campusVerified`（历史内容 authorVerified 展示层瑕疵，无功能性影响）。
- `npm audit` 41 项维持 L5「已接受风险」口径不变。
