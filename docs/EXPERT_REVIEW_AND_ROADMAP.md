## 1. 执行摘要（TL;DR）

### 1.1 总体评分卡

| 维度 | 得分 | 一句话结论 |
|------|:---:|------------|
| 代码工程质量 | ★★★★☆ 8/10 | 共享内核层设计优秀，安全默认值到位，远超个人项目平均水平 |
| 功能完整度 | ★★★★☆ 8/10 | 社区主链路齐全，缺"留存钩子"与"校园刚需工具" |
| 市场竞争力 | ★★★☆☆ 5/10 | "全国开源贴吧"定位冷启动难；必须收缩为**单校深耕** |
| 合规可上线性 | ★★☆☆☆ 4/10 | **P0 红线：个人主体无法选社区/论坛类目**，需先解决主体问题 |
| 部署易用性 | ★★☆☆☆ 4/10 | 34 函数逐个手动上传 + 32 个索引手动建，新人部署约 0.5~1 天 |
| 成本健康度 | ★★★★☆ 7/10 | 云开发起步近乎零成本；但 DB 调用次数是隐形大头，需按清单降本 |
| 可持续运营 | ★★★☆☆ 5/10 | 无备份、无监控告警、无自动化部署，单人维护风险集中 |

### 1.2 三条战略结论

1. **先解决"能不能上"，再谈"好不好"（合规 P0）**：「社交 > 社区/论坛」类目要求非个人主体。最优路径是挂靠学校社团/校团委主体注册，其次是注册个体工商户；小程序名称避开"社区/论坛/贴吧"字样。
2. **从"全国贴吧"收缩为"一校一署"（产品转向）**：README 中 "nationwide by default" 的定位会让每个新部署的学校都面对空城冷启动。改为：一套代码 → 一校一个云环境 → 校内深耕 → 跑通后向多校复制（这也是开源项目的自然传播模型）。
3. **成本与部署是个人开发者的生命线（工程重点）**：上线后免费环境仅保留 15 天，之后基础套餐 19.9 元/月起。当前代码在千级 DAU 下月费用约 40~70 元；按第 4 章降本清单改造后可压回套餐内。部署自动化能把新人上手成本从半天降到约 10 分钟。

## 2. 各专家组评估发现

### 2.1 产品组：定位与功能

**做对了的**
- 发帖/二手/楼中楼评论/关注/签到/通知，社区闭环完整；
- 任务帖自动过期 + 已解决标记——同类产品少有的"信息保鲜"设计；
- 分类树三级管理后台化，加学校/开新版块零代码。

**核心问题：冷启动死锁**
- 全国默认内容池 + 无推荐算法 = 新用户进来看到按时间排序的空列表。社区产品的第一印象由"前 10 条内容"决定，而全国池对任何单一学校的用户都是空的。
- tabBar 只有 首页/指南/我的，二手市场（最高频刚需之一）藏在首页 tab 内，曝光不足。

**功能优先级重排建议**

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 | 失物招领模块 | 校园最强刚需、天然传播（捡到/丢失双方都会拉人来看）、复用帖子体系改造成本低 |
| P0 | 校园身份认证（学号 / edu 邮箱） | 二手交易信任基石 + UGC 实名义务的技术兜底 |
| P1 | 订阅消息（回复/关注的新帖提醒） | 小程序最大痛点是召回，订阅消息是唯一免费推送通道 |
| P1 | 二手独立 tab 入口 | 高频功能给一级入口 |
| P1 | 表白墙模式（强匿名短内容） | 校园流量之王，需配合审核策略 |
| P2 | 新生专区（9 月季） | 攻略/找老乡/问答，一年一度的拉新增长期 |
| P2 | 空教室/课表等轻工具钩子 | 工具带社区；非刚需不做重 |

### 2.2 技术组：架构与代码

**值得保持的资产**
- `cloudfunctions/common/` 单一事实内核：鉴权、内容安全 fail-closed、封禁拦截、限流、删除回收，一处修改全局生效——架构上是教科书式的；
- `hasMore` 用 `length === size` 而非额外 `count()`，省一半读次数（post-list/index.js:32）;
- 状态白名单、NaN-safe 价格、正则转义防注入等细节到位。

**技术债清单**

| # | 问题 | 位置 | 影响 |
|---|------|------|------|
| T1 | 限流每次写操作都多一次 `count()` 读 | common-rate.js:13-15 | DB 读次数≈写操作数翻倍，最大隐性成本项之一；索引缺失时退化为全表扫 |
| T2 | 搜索用正则匹配 title+content | search/index.js | 正则不走索引=全表扫描；数据过万后延迟与费用失控 |
| T3 | 34 个云函数逐个手动上传 | docs/DEPLOY.md 第四步 | 新人部署最大摩擦点；改一行公共代码要重新传 34 个函数 |
| T4 | 32 个数据库索引仅能控制台手动建 | docs/DEPLOY.md 第七步 | 平台硬约束，但应提供可导入 JSON 与校验脚本（init-db 已有 missingIndexes 自检，好） |
| T5 | 零测试覆盖 | ci.yml 仅校验 package.json | 公共层改动无回归保护；v0.6.0 曾因此出现 P0 回归（见 CHANGELOG） |
| T6 | 无数据备份策略 | — | 学校运营数据丢失即事故；免费版无自动备份 |
| T7 | task-expire 每小时 cron 扫描 | task-expire | 可改"惰性过期"（查询时顺带标记）+ 低频兜底 cron，省调用次数 |
| T8 | 图片压缩链路未确认 | post-create 等 | CDN 流量 210 点/GB 是图片社区账单大头，原图直传贵 3-5 倍 |

### 2.3 安全合规组 ⚠️ 本次评审最重要章节

**P0-1 主体资质红线（2026 年现行规则，已调研确认）**
- 「社交 > 社区/论坛」类目**不支持个人主体**，UGC 论坛类服务要求企业/组织主体及备案资质；
- 个人主体可选类目以"工具、信息查询"为主，硬闯会被驳回甚至封禁；
- 小程序名称含"社区/论坛/贴吧"字样会触发资质审查。

**可行路径（按推荐顺序）**

| 路径 | 成本 | 说明 |
|------|------|------|
| A. 挂靠学校社团/校团委主体 | ≈0 元 | 用社团组织主体注册认证小程序；校园场景最容易谈成，自带官方背书与推广渠道。**首选。** |
| B. 注册个体工商户 | 0~200 元注册 + 约 300 元/年认证 | 类目比个人宽得多，可线上办理；适合社团谈不下来时 |
| C. 企业代注册/购买主体 | 数千元起 | 现阶段不推荐 |

**配套合规动作（无论选哪条路径）**

1. 改名示例：`XX校园通` / `XX百事盒` / `XX校园帮`（避开敏感词）；
2. 完成**小程序 ICP 备案**（公众平台内提交，免费）；
3. 补隐私政策页（现仅有 agreement 用户协议页）；收集头像昵称需声明用途；
4. UGC 平台义务自查：后台实名（openid 不足以对抗检查，学号绑定可作技术兜底）、举报通道✅已有、内容审核✅fail-closed（本项目亮点）、违法内容留存与配合调取流程写入 SECURITY.md；
5. 个人主体拿不到 getPhoneNumber 授权——校园认证走 edu 邮箱验证码或学号人工审核。

**其余安全发现**
- INIT_SECRET 保护 init-db ✅；ADMIN_OPENIDS 环境变量 ✅；
- 建议：admin 敏感操作（封禁、批量删帖）加二次确认；导出类操作加审计日志集合。

### 2.4 运维部署组：部署体验

量化现状：DEPLOY.md 十步流程中，第四步（34 函数）+ 第七步（32 索引）占新人部署时间 80% 以上，实测约 0.5~1 天；改一行公共代码要重复上传 34 次。

**改造方案（详见 §5）**
1. `miniprogram-ci` 的 `ci.cloud.uploadFunctions` 批量部署全部云函数（官方能力，需在小程序后台上传"代码上传密钥"）；
2. GitHub Actions：push 到 main → 同步 common → 批量部署函数+触发器 → 输出 missingIndexes 报告；
3. 本地 `npm run deploy` 等效脚本；
4. `doctor` 自检脚本：一键检查 AppID / 环境 ID / 函数数量 / 索引缺失 / 触发器状态。

### 2.5 FinOps 成本组：资金紧张专项

**2026 年现行计费要点（官网口径实测）**
- 微信云开发免费体验环境：每账号 1 个；**小程序发布上线后第 15 天到期**，到期须转付费否则停服清数据；活动截至 2026-12-31；
- 基础套餐 **19.9 元/月**（原价 39 元，5 折长期有效），约 40,000 资源点/月；资源点换算：1000 点 = 1 元；
- 主要单价：数据库读写 **200 点/万次**、云函数调用 13.3 点/万次、CDN 流量 210 点/GB、云存储容量 3.94 点/GB/天；
- 腾讯云「AI 应用及线上工具小程序成长计划」（2026 全年）：新开发者可领免费个人版环境 6 个月 + AI 资源包；已有环境可领 120 元代金券。**建议立即报名领取**；
- 流量主广告：UV ≥ 500 即可开通 banner 广告，个人主体也能开——**覆盖每月 19.9 元的直接收入来源**。

**成本模型估算（粗估，以实际账单为准）**

假设：人均日会话 20 次请求、每请求平均触发 3 次 DB 读写、图片已压缩。

| DAU | 月 DB 调用 | 月函数调用 | 估算资源点 | 未优化月费 | 优化后 |
|----:|----------:|----------:|-----------:|-----------:|-------:|
| 300 | ~54 万 | ~18 万 | ~1.4 万点 | 套餐内 ≈0 元 | 0 元 |
| 1000 | ~180 万 | ~60 万 | ~4.5 万点 | ≈25~45 元 | ≈19.9 元（套餐内） |
| 3000 | ~540 万 | ~180 万 | ~13 万点 | ≈130 元 | ≈50~70 元 |

> 结论：单校场景（500~3000 人）执行降本清单后，**月成本可稳定控制在 19.9~50 元**，流量主收入足以覆盖。

**降本改造清单（按 ROI 排序）**

| # | 措施 | 预期降幅 | 改动量 |
|---|------|---------|--------|
| C1 | 前端上传前 `wx.compressImage` 压缩图片（长边 ≤1280px），瀑布流用压缩图 | CDN+存储 -50%以上 | 小 |
| C2 | 首页列表第一页 + 分类树本地缓存（storage，TTL 5 分钟） | DB 读 -20% | 小 |
| C3 | task-expire 改惰性过期：列表/详情查询时顺带标记过期，cron 降为每 6 小时兜底 | 函数调用 -90%（该项自身） | 中 |
| C4 | rateLimit 复用业务集合计数（如 post-create 直接查当日该用户发帖数，不再单独 count） | DB 读 -15~25% | 中 |
| T5'→C5 | 通知未读数改为进个人中心时刷新一次，去掉高频轮询 | DB 读 -10% | 小 |
| C6 | 云函数内存统一降为 256MB（默认即 256MB 则维持；勿设 512MB+） | 函数 GBs 费用对半 | 小 |
| C7 | 搜索限频（每用户 10 秒 1 次）+ 仅搜标题前缀优先 | 全表扫成本可控 | 小 |

### 2.6 市场增长组 + 高校顾问：竞争力与冷启动

**竞品格局（2026）**

| 竞品 | 强项 | 弱点（我们的机会） |
|------|------|------|
| 百度贴吧（校园吧） | 存量内容多 | 产品老化、广告多、移动端体验差 |
| 表白墙 QQ 群/公众号 | 渗透率极高 | 无结构化（二手检索难）、信息流噪音大、无沉淀、无搜索 |
| 超级课程表/到梦空间/易班 | 工具+官方属性 | 社区弱、无本校氛围 |
| 闲鱼/转转 | 二手供给大 | 无校内信任圈，当面交易不便 |
| 同类单校小程序 | 多 | 功能浅、闭源、无运营方法论 |

**差异化定位：「开源校园社区操作系统」**
- 对学生：一个校内可信的"贴吧 + 闲鱼 + 失物招领 + 攻略库"；
- 对社团/学校：可自部署、零成本、管理后台开箱即用的官方社区底座；
- 对项目本身：每多一所学校部署 = 一份真实案例与 Star，形成"一校一署"联盟效应。

**冷启动打法（单校 0→500 人）**
1. **种子内容先行**：上线前灌 50 篇攻略（新生指南/选课/食堂测评），杜绝空城；
2. **开学季窗口**（每年 9 月）：新生群投放 + 宿舍海报二维码 + "学长学姐问答周"活动；当前正值 8 月末，**这是今年最好的启动时机**；
3. **校园大使体系**：招募 5~10 名 KOC 给管理员权限 + 简历背书 + 运营手册（docs 里应新增 OPERATIONS.md）；
4. **失物招领地推**：与校保卫处/宿管合作，拾获物品统一挂平台——刚需且官方乐意；
5. **信任背书**：走合规路径 A（社团主体）后，以"XX大学官方社团共建"名义宣传。

## 5. 部署自动化目标架构（v0.7 实施）

```
git push → GitHub Actions
  ├─ npm install && npm run sync:common        # 内核同步
```

- 本地等价命令：`npm run deploy -- --env dev`；
- 索引：优先尝试 @cloudbase/manager-node 的索引 API 自动创建；不可用则回退"导出 JSON 清单 + 控制台导入"，并保留 init-db 的 missingIndexes 自检作为验收。
