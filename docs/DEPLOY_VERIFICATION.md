# 上线验证记录（v0.9.5 网关收敛）

> 用途：网关收敛 + 两个定时器函数的**一次跑完、逐项留痕**。每格填 `通过 / 失败 / 待查`，失败必须写现象与函数日志位置。
> 环境：先 dev，后 prod。记录按环境各存一份。

## 一、部署单元清单（10 个）

| 部署单元 | 承载入口数 | 触发方式 | 需要控制台配置 | 冒烟要点 |
|---|---|---|---|---|
| api-auth | 4 | 客户端调用 | HTTP 访问服务 + 鉴权（H5/App） | 登录、资料读写、校园认证 |
| api-post | 7 | 客户端调用 | 同上 | 带图发帖、编辑、删除、过期可见性 |
| api-product | 5 | 客户端调用 | 同上 | 发品、改价、标记已售 |
| api-comment | 3 | 客户端调用 | 同上 | 楼层 + 子回复 + 级联删除 |
| api-social | 6 | 客户端调用 | 同上 | 点赞/收藏/关注/通知/签到/积分 |
| api-admin | 6 | 客户端调用 | 同上 | 举报审核、类目 CRUD、公告 |
| api-content | 3 | 客户端调用 | 同上 | 指南列表、跨集合搜索 |
| task-expire | 1（独立） | **定时 6h** | 触发器已随函数保留 | 见第三节 |
| backup-db | 1（独立） | **定时 03:00** | 触发器已随函数保留 | 见第三节 |
| init-db | 1（独立） | 控制台手动 | 环境变量 `INIT_SECRET` | 集合与索引齐备 |

负向用例（全部环境都要跑）：

- `api-post` 传 `fn:'admin'` → 期望 `UNKNOWN_FUNCTION`（跨网关不得越权）
- `api-post` 传 `fn` 缺省 / 对象 / 数组 / 超长串 → 期望全部 `UNKNOWN_FUNCTION`
- 前端调用未登记函数名 → 期望客户端直接抛「未登记的云函数调用」，不发请求

## 三、两个定时器（本轮纳入同一份记录）

### task-expire（`0 0 */6 * * *`，每 6 小时）

代码事实（核对用，勿凭印象判断）：

- 批量 `where` 条件更新，把 `kind:'task'` 且未 `resolved`、已过 `expireAt` 的帖子置为 `expired`；信息流读侧本已惰性排除过期任务，此 cron 是归档兜底，**它挂了不会让过期帖留在首页**。
- 顺带跑 `reconcileUserCounts` 对账 `postCount/productCount`，best-effort，失败只告警不阻断。
- 清理：`view_logs` 保留 **90 天**；`rate_limits` 清 `expireAt` 已过期的窗口占位，**每次最多 500 条**，余量下次触发再清。
- 守卫：定时上下文无 OPENID → 放行；客户端手动调用 → 必须命中 `ADMIN_OPENIDS`，否则 `FORBIDDEN`。

| 检查项 | 期望 | 记录 |
|---|---|---|
| 手动构造一条 `expireAt` 已过期的任务帖，等下一次整点触发 | 状态变 `expired`，出现在「过期」页、不在首页 | |
| 非管理员从客户端调用该函数 | `FORBIDDEN` | |
| 管理员（已配 `ADMIN_OPENIDS`）手动调用 | 正常执行，返回统计 | |
| 连续两天观察 `rate_limits` 文档数 | 不单调上涨（说明清理在生效；本轮新增了 6 个限频场景，写入量会高于旧版） | |
| 函数日志 | 无未捕获异常；对账失败只出现 `[reconcileUserCounts]` 告警级日志 | |

### backup-db（`0 0 3 * * *`，每日 03:00）

代码事实：

- 快照写入 `backups` 集合（JSON 分片），保留天数由环境变量 `BACKUP_RETENTION_DAYS` 控制，**默认 7**。
- 单集合最多 `MAX_PARTS_PER_COLLECTION = 40` 片（约 2 万条）；达到上限仍有剩余时，`summary` 标记 `truncated:true`，**不静默丢数据**。
- 旧备份清理每次最多 500 条。
- 守卫同 task-expire：定时放行、手动需管理员。

| 检查项 | 期望 | 记录 |
|---|---|---|
| 首次触发后 `backups` 有新快照文档 | 每集合一条记录含 `total` / `parts` | |
| 存在超 2 万条的集合 | `truncated:true` 显式出现在 summary，并能据此判断缺口 | |
| 第 8 天 | 第 1 天的快照已被清理（保留期生效） | |
| 手动恢复演练 | 用 `backups` 数据能重建任一集合样本，条数与 `total` 一致 | |
| 云存储/数据库容量 | 备份是分片写库，注意数据库容量配额，必要时调小 `BACKUP_RETENTION_DAYS` | |

## 四、收尾：删除旧的 37 个云函数（必须在观察期之后）

观察期建议 1–2 周。顺序不可颠倒——旧函数是唯一的回滚锚点。

1. `useGateway` 保持 `true`，确认新流量全走网关（看 7 个网关调用量、旧 37 个函数调用量归零）。
2. 控制台逐个删除旧函数目录：**先删只读类**（`*-list`、`*-detail`、`guide-*`、`search`），再删写入类（`*-create`、`*-update`、`*-delete`、`checkin`、`points`），最后删 `admin` / `category-manage` / `resolve` / `verify`。
3. `task-expire`、`backup-db`、`init-db` **不删**（它们就是最终的独立函数）。
4. 删除后复查：配额页显示云函数数量 = 10；`npm run gate` 仍为 0（源码侧早已不含旧目录）。

## 五、本仓无法自证、必须在云环境确认的点

- 网关形态下 `getWXContext()` 的身份传递（客户端直连网关，理论无损，但需真机复核 `login` 返回的 openid 与发帖归属一致）。
- `imgSecCheck` 同步 Buffer 形态的真机返回（沙箱只能断言调用形态，不能替代真实接口）。
- 冷启动耗时：网关一次装载组内全部 handler，首次调用会比单入口函数略重。
- H5/App 的 REST 端点：7 个网关都要单独开 HTTP 访问服务并配鉴权，漏配表现为 H5 端 401 而小程序端正常。
